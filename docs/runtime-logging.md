# 运行故障日志

管理员可在“系统 → 调试配置”开启运行故障日志。开关保存后立即生效，不需要重启服务；关闭后只停止新增记录，原有文件仍可在后台预览或下载。

后台的“打开日志目录”按钮只允许打开运行服务电脑上的固定日志目录。后端会确认服务进程与 `explorer.exe` 位于同一个交互桌面会话，PowerShell 确认启动成功后才返回成功提示；通过本机局域网 IP、主机名或代理入口访问不会再被误判。远程浏览器只能触发服务器电脑上的资源管理器，Windows Session 0 服务、Docker 或无图形桌面的 Linux 服务则无法显示窗口，此时应使用“复制目录路径”后到服务器上手动查看。

选择日志文件后可点“查看原始日志”，直接在后台弹窗阅读 JSONL 文本。弹窗默认从文件末尾读取 256 KiB，可继续加载更早内容、刷新到最新状态或下载完整文件，避免一次加载大文件导致页面卡顿。

日志统一位于运行数据目录的 `logs/` 子目录，默认即 `data/logs/`。源码运行包以及 Windows、Linux、macOS 便携运行包使用相同规则；配置 `GPT_IMAGE_DATA_DIR` 时，日志目录随数据目录移动。

系统记录服务端警告和错误、API 5xx、超过 30 秒的普通 API 请求、进程级未捕获异常，以及已登录用户或管理员页面的浏览器异常。日志不会保存请求或响应正文、提示词、图片、Cookie、Authorization、API Key、密码和 Token，异常对象与 URL 在写入前还会统一脱敏和截断。

文件采用 `runtime-YYYY-MM-DD[-N].jsonl` 命名。JSONL（JSON Lines）表示每一行都是一条独立的 JSON 日志，便于服务持续追加、后台从文件尾部读取和按字段筛选；即使某一行意外损坏，也不会影响其它日志。它可以直接用记事本、VS Code 等文本工具打开。单文件达到 20 MiB 后轮转，保留 14 天并限制总量不超过 200 MiB。运行日志不会进入应用数据备份。

新日志的 `timestamp` 使用运行服务电脑的本地时间，并带明确的数字时区偏移，例如中国标准时间写为 `2026-09-17T11:23:01.258+08:00`。早期版本已经写入的 `Z` 结尾时间仍表示 UTC，后台能够继续正常解析和显示。

应用内日志无法可靠记录 OOM、断电、操作系统强制终止或容器被直接杀死的最后时刻。遇到这些情况，应同时检查 systemd、Docker、托管面板或 Windows 系统日志中的退出原因。
